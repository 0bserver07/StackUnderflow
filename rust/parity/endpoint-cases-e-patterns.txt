# Batch E / member `patterns` — case rows for `routes/patterns.py` (RS-5-088/089).
#
# Format and conventions: see the header of `parity/endpoint-cases.txt`. The
# integrator merges these rows into that file and strips the leading
# `P-by-dir-known` selection row, which already runs earlier there.
#
# THE HEADLINE, and it decides the shape of this whole file:
#
#   `GET /api/patterns` puts a WALL CLOCK in its 200 body.
#   `reports/patterns.py:653-656` computes
#       since_iso = (datetime.now(UTC) - timedelta(days=days)).isoformat()
#   and `:1055` emits it as `report.window.since`. `.isoformat()` on an aware
#   datetime renders MICROSECONDS. Two servers answering the same case a few
#   milliseconds apart emit different bytes; so does one server answering twice.
#
#   Therefore EVERY 200 on this endpoint is permanently `!`, by construction —
#   structurally DIV-085 (`/api/compare`'s `generated = time.time()`), reached
#   through a different module. `!PT-patterns` and `!PT-patterns-window` are not
#   "not yet flipped", they are NOT FLIPPABLE, and the two blocks below are split
#   on exactly that line. Both endpoints are nevertheless fully ported: the
#   arithmetic under the clock is covered by 55 unit tests, which is the only
#   place it can be covered.
#
#   `PT-bad-since` reads no clock. It flips, and every other validator leg beside
#   it flips with it (law 5).
#
# SIDE EFFECTS of the rows below: NONE. Every row is a `GET` or an unclaimed
# method on `/api/patterns`. The handler opens the store through
# `store/db.py::connect` on both sides (read-write handle, SELECT-only use,
# plus Python's idempotent `schema.apply`) and `mine_patterns` is `sqlite_master`-
# guarded SELECTs throughout. Nothing under `$STACKUNDERFLOW_HOME` is written.
#
# `POST /api/patterns/dismiss` (RS-5-089) HAS NO ROW HERE, AT ANY STATUS.
# It bumps a `dismissed` counter in `proactive_state.json`, so python-then-rust
# leaves `2` where either alone leaves `1` — non-idempotent under the differ's one
# shared home, which is law 4 / DIV-146's ruling. See `DIV-e-patterns.md` finding
# 2 for the correction to DIV-144's stated reason (the file is NOT outside
# `$STACKUNDERFLOW_HOME`; it is `deps.store_path.parent/proactive_state.json`),
# and finding 10 for the four 422 legs this leaves unprobed — a known, instructed
# law-5 gap, not an oversight.
#
# NOT CLAIMED: `GET /api/patterns/` (trailing slash). That is DIV-133, the
# architect's `lib.rs` item, and adding a row for it here would re-raise a
# dispositioned divergence under a new id.
