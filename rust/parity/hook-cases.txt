# The hook differ's corpus — one recorded hook invocation per line.
#
# Every line is one fire of `hooks run <id>` with a recorded stdin payload, run
# by BOTH implementations against their own copy of the same store state, and
# compared on stdout bytes, stderr bytes, exit code, the `captured_events` rows
# each one wrote, and the governance JSON each one left behind.
#
# Columns, TAB-separated:
#
#   id        the case name; `!` prefix = KNOWN-OPEN (reported, does not fail)
#   hook_id   the argument to `hooks run`
#   flags     `-` or `capture` (adds --capture-content)
#   env       `-` or `K=V,K=V` — extra environment for BOTH sides
#   stdin     the payload, verbatim on one line; `-` means empty stdin
#
# The payloads are the shapes Claude Code actually pipes (`hook_event_name`,
# `session_id`, `cwd`, `tool_name`, `tool_input`, `tool_response`, `prompt`,
# `trigger`, `stop_hook_active`), plus the malformed ones the reference's own
# tests cover, plus the payload shapes that pick out a specific branch of the
# heuristics — a bool exit code, a float exit code, `"--5"`, a stopword-only
# prompt, a notebook path, a non-dict `tool_input`.
#
# The store state is `parity/build_hook_state.py`'s synthetic home. It is
# synthetic on purpose: the maintainer's real `tools_json` is a names-only
# array, so `find_failure_modes_for_file` matches nothing on it and four of the
# nine hooks would be compared only in their silent branch. See that file's
# docstring.
