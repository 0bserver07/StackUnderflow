## Not divergences — inherited faithfully, listed so nobody "fixes" them

* **The `+1` is collected twice per turn.** `tokens = _estimate_tokens(content) + _estimate_tokens(tool_payload)`, and `_estimate_tokens` is `len // 4 + 1` on any non-empty string. A message with both text and tool calls therefore gets `+2` of pure rounding. Ported as written; the running total is documented by the reference as "a shape, not an invoice".
* **`total_tokens` after a slice is not a sum.** It is `kept[-1]["cumulative_tokens"]`, read straight off the last retained event. Correct only because `seq` is monotonic in the build; a re-ordered `events` array would give a silently wrong total. Ported as written.
* **`seq` is not per-session-sequential** in the real store — `04a86c63-…` has three messages at `seq` 2369/3036/3576 and `44b8f238-…` spans 1285 … 5832062. `?at=1` therefore keeps *nothing* on a real session, which is worth knowing before writing a case row or a UI slider.
* **The two resolvers catch different exception types.** The route's `_resolve_session_row` catches bare `Exception`; the service's `_resolve_session` catches `sqlite3.Error`. Every driver exception derives from `sqlite3.Error`, so the widths coincide in practice. Both ported as total swallows.
* **The fence's failure default is the opposite of the resolver's.** `_scope_project_ids` swallows a store error into `[]` — fence *everything* — while the resolvers swallow into "unknown session". Getting the fence's default backwards would leak another project's transcript, so it is called out here and pinned by `a_broken_store_fences_everything_rather_than_opening_the_gate`.
* **`build_context_timeline`'s error warning interpolates the driver's message** (`f"could not read messages: {exc}"`). rusqlite's `Display` for `SqliteFailure(_, Some(msg))` prints `msg`, which is SQLite's own string — the same text CPython's `sqlite3.OperationalError` carries. A rusqlite-*specific* error kind (`InvalidColumnType`, …) would print differently, but this statement cannot raise one on a real store.

## Flagged for the architect's dedup list

* `summarize_tool_call` and its whole supporting cast (`_short_path`,
  `_first_command_word`, `_input_path`, `_mcp_label`, the 27-entry
  `_SUMMARY_HANDLERS`) belong to `services/playback.py`, whose slot is still an
  unported stub. They are ported **privately** inside
  `services/context_replay.rs` and `summarize_tool_call` is `pub` precisely so
  the playback batch can lift it out rather than write a second copy.
* `py_isspace` / `py_strip` — CPython's whitespace set is `White_Space` **plus
  `U+001C..=U+001F`**, which `char::is_whitespace` omits. Every port that
  transliterates a `.strip()` truthiness test needs this and `trim()` is the
  wrong answer. Currently `pub(crate)`-shaped in `services/context_replay.rs`
  (the route imports `py_strip` from it rather than keeping a fourth copy).
* `py_first_line` — `str.splitlines()[0]`, which breaks on eleven separators.
* `char_prefix` and `validation_detail` are the fifth and third copies
  respectively; already on the list from batches A and B.
